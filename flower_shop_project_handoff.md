# Цветочный магазин — технический бриф и передача проекта

Дата актуализации: 17 сентября 2026 года.

## 1. Общая задача

Нужно создать небольшой сайт цветочного магазина. В качестве ориентира первоначально рассматривался сайт:

- https://www.malina66.ru/

Задача не состоит в полном копировании этого сайта. Нужна упрощённая самостоятельная версия с основными функциями:

- лендинг цветочного магазина;
- витрина товаров и категорий;
- корзина;
- оформление заказа;
- сохранение заказов;
- простая административная панель;
- уведомление администратора о заказе через Telegram;
- адаптация для компьютеров и телефонов.

Первая версия должна быть простой, недорогой в размещении и понятной в обслуживании. Полноценная сложная платформа, мобильное приложение, складской учёт, CRM, интеграция с 1С и онлайн-оплата на первом этапе не требуются.

## 2. Что реально можно сделать с помощью AI

С помощью AI можно подготовить практически всю техническую часть базового магазина:

- разработать дизайн и адаптивную вёрстку;
- написать HTML, CSS и JavaScript;
- реализовать корзину и оформление заказа;
- разработать серверную часть на PHP;
- спроектировать базу MySQL;
- сделать административную панель;
- подключить Telegram Bot API;
- подготовить инструкции по размещению на REG.RU;
- помочь с настройкой домена, HTTPS и базы данных;
- находить и исправлять ошибки.

От владельца проекта потребуются:

- покупка домена и хостинга;
- доступ к панели REG.RU;
- названия, цены, описания и фотографии товаров;
- контакты, адрес, условия доставки и оплаты;
- создание Telegram-бота через BotFather;
- безопасная передача токена бота и ID чата при подключении;
- проверка готового сайта и принятие бизнес-решений.

Базовый функционал реализуем полностью. Полное повторение крупного интернет-магазина тоже технически возможно, но потребует отдельного технического задания, большего времени, более серьёзного тестирования и, вероятно, VPS.

## 3. Выбранный вариант размещения

Для первой версии рекомендуется:

- домен на REG.RU;
- обычный виртуальный хостинг REG.RU;
- PHP для серверной части;
- MySQL для базы данных;
- HTML, CSS и JavaScript для интерфейса;
- Telegram Bot API для уведомлений.

Для такого проекта VPS на старте не обязателен. Обычного хостинга достаточно, если посещаемость небольшая, а сайт не использует постоянно работающий Node.js-процесс, Docker, WebSocket или тяжёлые фоновые задачи.

### Что где будет находиться

| Компонент | Где находится |
|---|---|
| Домен | Зарегистрирован на REG.RU и указывает на хостинг |
| Страницы сайта | В папке сайта на хостинге |
| PHP-код | На том же хостинге |
| Фотографии товаров | В папке uploads или аналогичной папке на хостинге |
| База MySQL | На инфраструктуре того же тарифа хостинга REG.RU |
| Админка | Защищённый раздел сайта, например `/admin/` |
| Telegram-бот | Создаётся в Telegram; сайт обращается к Telegram Bot API |
| Исходный код | Может дополнительно храниться в GitHub |

Физически MySQL может работать на отдельном сервере провайдера, но для владельца она входит в услугу хостинга и управляется из той же панели REG.RU.

## 4. Почему одного домена недостаточно

Домен — это только адрес сайта, например `flowers.ru`. Он не хранит страницы, товары и заказы.

Для работы сайта требуется место, где находятся файлы и выполняется серверный код. Это место предоставляет хостинг или VPS.

Итоговая минимальная покупка:

1. Домен.
2. Виртуальный хостинг с PHP и MySQL.

GitHub полезен для хранения истории исходного кода, но сам по себе не заменяет серверную часть магазина. GitHub Pages подходит для статической страницы, однако безопасно хранить заказы, админку, базу и секретный токен Telegram-бота там нельзя.

## 5. Хостинг и VPS — простое сравнение

### Обычный хостинг

Это готовая комната в большом доме. Провайдер уже настроил PHP, MySQL, HTTPS, резервные копии и панель управления. Пользователь загружает файлы и создаёт базу.

Плюсы:

- дешевле;
- проще настроить;
- не требуется администрировать Linux;
- подходит для небольшого магазина;
- PHP и MySQL уже предусмотрены.

Минусы:

- ограниченные ресурсы;
- нет полного доступа к операционной системе;
- нельзя свободно запускать Docker и постоянный Node.js-сервер;
- меньше возможностей для нестандартных фоновых сервисов.

### VPS

VPS — это виртуальный сервер: отдельный компьютер в дата-центре, который работает круглосуточно и имеет публичный IP-адрес.

На VPS можно разместить сайт, базу, Telegram-бота, файлы и другие сервисы. Владелец получает полный контроль, но обязан самостоятельно настроить и защищать сервер.

Плюсы:

- полный доступ к Linux;
- можно использовать Docker, Node.js, PostgreSQL и фоновые службы;
- гибкая настройка;
- проще масштабировать нестандартные решения.

Минусы:

- дороже обычного хостинга;
- сложнее настройка;
- нужно следить за обновлениями, безопасностью, резервными копиями и работой сервисов.

Если выбирать VPS, для небольшого проекта обычно достаточно ориентировочно 2 ядер, 2–4 ГБ оперативной памяти и 20–40 ГБ диска. Но для текущей простой архитектуры VPS не нужен.

## 6. Обсуждавшиеся лимиты REG.RU Host-0

В разговоре рассматривался базовый тариф Host-0. Упоминались следующие лимиты:

| Параметр | Обсуждавшийся лимит |
|---|---:|
| Отдельные сайты | 7 |
| Общий диск | 26 ГБ |
| Файлы сайта, изображения и почта | 13 ГБ |
| Базы MySQL суммарно | 13 ГБ |
| Одна база MySQL | до 4 ГБ |
| Количество баз | неограниченно |
| Файлы и папки | до 150 000 объектов |
| Трафик | безлимитный |
| Ориентир для статического сайта | около 2 000 посетителей в сутки |
| Одновременно работающие PHP-процессы | 4 |
| Все одновременно работающие процессы | 36 |
| Память на один процесс | до 1 ГБ |
| HTTP-запросы на один домен | до 150 в секунду |
| Cron-задания | поддерживаются |
| HTTPS | включён |
| Резервные копии | заявлены провайдером |

Эти значения и актуальную стоимость необходимо повторно проверить на REG.RU непосредственно перед покупкой: тарифы и условия могут измениться.

Для магазина с десятками или сотнями посетителей в сутки, небольшим каталогом и одним администратором такого тарифа должно хватить с запасом.

## 7. Что означают PHP, Node.js и Docker

### PHP

PHP — язык, который выполняется на сервере. Для этого проекта он может:

- получать заказ из формы;
- проверять введённые данные;
- записывать заказ в MySQL;
- отправлять сообщение в Telegram;
- показывать товары из базы;
- обслуживать административную панель.

PHP хорошо подходит для обычного виртуального хостинга REG.RU.

### Node.js

Node.js позволяет выполнять JavaScript на сервере. На нём тоже можно написать магазин, API и Telegram-бота. Однако постоянно работающий Node.js-сервер обычно неудобен или недоступен на самом дешёвом обычном хостинге. Для него чаще выбирают VPS или специализированную платформу.

Для текущего проекта Node.js не обязателен. JavaScript в браузере и PHP на сервере — более простой вариант.

### Docker

Docker запускает приложение в изолированном контейнере вместе с его зависимостями и настройками. Это помогает одинаково запускать проект на разных серверах.

Docker полезен для сложных проектов и VPS, но на обычном виртуальном хостинге, как правило, недоступен и текущему магазину не требуется.

## 9. Как должен проходить заказ

1. Покупатель открывает витрину.
2. Выбирает категорию.
3. Добавляет товары в корзину.
4. Меняет количество или удаляет товар.
5. Открывает корзину и видит состав и сумму.
6. Переходит к оформлению заказа.
7. Вводит имя, телефон, адрес, дату, время и комментарий.
8. Браузер отправляет данные PHP-обработчику.
9. PHP повторно проверяет цены и товары по базе.
10. Заказ и его позиции записываются в MySQL.
11. PHP отправляет администратору сообщение через Telegram Bot API.
12. Покупатель видит подтверждение и номер заказа.
13. Администратор открывает заказ в админке и связывается с покупателем.

Пример уведомления Telegram:

```text
Новый заказ №124

Покупатель: Анна
Телефон: +7 900 000-00-00
Адрес: улица, дом, квартира

Состав:
— Букет №01 × 2 — 6 980 ₽
— Клубника в шоколаде × 1 — 1 790 ₽

Итого: 8 770 ₽
Дата и время: 18 сентября, 16:00
Комментарий: позвонить перед доставкой
```

Для простой отправки уведомления постоянно запущенный Telegram-бот не нужен: PHP вызывает метод `sendMessage`. Webhook понадобится, если администратор должен нажимать кнопки в Telegram, менять статус заказа или отвечать боту командами.

## 10. Административная панель

Минимальная админка должна включать:

- вход по логину и паролю;
- список заказов;
- просмотр состава и контактов покупателя;
- изменение статуса заказа;
- добавление, редактирование и скрытие товаров;
- изменение цены;
- управление категориями;
- загрузку фотографии товара;
- изменение порядка товаров;
- управление акционными слайдами.

Рекомендуемые статусы заказа:

- новый;
- подтверждён;
- собирается;
- передан в доставку;
- выполнен;
- отменён.

Админка может состоять из нескольких PHP-страниц. Обычный хостинг не ограничивает сайт одной страницей.

## 11. Безопасность

Обязательные меры:

- хранить пароль администратора только как `password_hash`;
- использовать PHP-сессии;
- защитить формы от CSRF;
- проверять данные и на клиенте, и на сервере;
- использовать подготовленные SQL-запросы;
- ограничивать формат и размер загружаемых файлов;
- не хранить токен Telegram в публичном JavaScript или GitHub;
- включить HTTPS;
- ограничить количество попыток входа;
- регулярно делать резервные копии базы и фотографий;
- не доверять итоговой сумме, присланной браузером: пересчитывать её по базе.

## 14. План дальнейшей разработки

### Этап 1. Утвердить интерфейс

1. Проверить текущий макет на телефоне и компьютере.
2. Утвердить порядок блоков.
3. Утвердить категории.
4. Заменить демонстрационные названия и цены.
5. Добавить настоящие фотографии и название магазина.
6. Утвердить форму оформления заказа.

### Этап 2. Подготовить размещение

1. Купить домен.
2. Купить виртуальный хостинг REG.RU с PHP и MySQL.
3. Добавить домен в панель хостинга.
4. Создать базу MySQL и пользователя базы.
5. Включить бесплатный SSL-сертификат.

### Этап 3. Разработать серверную часть

1. Создать структуру базы.
2. Подключить PHP к MySQL.
3. Перенести товары из HTML в базу.
4. Сделать API или PHP-вывод каталога.
5. Реализовать оформление заказа.
6. Пересчитывать цены на сервере.
7. Записывать заказ и позиции в базу.

### Этап 4. Подключить Telegram

1. Создать бота через BotFather.
2. Получить токен.
3. Определить ID администратора или группового чата.
4. Сохранить токен вне публичной папки сайта.
5. После записи заказа вызывать `sendMessage`.
6. Проверить сообщения и обработку ошибок Telegram.

### Этап 5. Сделать админку

1. Реализовать вход.
2. Добавить управление товарами и категориями.
3. Добавить загрузку фотографий.
4. Добавить список и карточку заказов.
5. Добавить изменение статусов.
6. Добавить управление промослайдами.

### Этап 6. Тестирование и запуск

1. Проверить мобильную версию.
2. Проверить корзину и разные количества.
3. Проверить пустую корзину.
4. Проверить обязательные поля формы.
5. Проверить создание заказа в MySQL.
6. Проверить Telegram-уведомление.
7. Проверить вход и выход из админки.
8. Проверить загрузку неправильных файлов.
9. Сделать резервную копию.
10. Разместить сайт и направить домен на хостинг.

15. Нужно ли хранить корзину после закрытия браузера?

## 16. Рекомендации следующей нейросети

- Не менять текущий общий стиль без прямого указания пользователя.
- Сначала продолжать работу с существующим макетом, а не создавать новый дизайн с нуля.
- При размещении на обычном хостинге использовать PHP и MySQL.
- Не предлагать Docker и постоянно работающий Node.js без перехода на VPS.
- Не помещать Telegram-токен в JavaScript, HTML или публичный GitHub.
- Реальную сумму заказа всегда пересчитывать на сервере.
- Сохранять заказ в MySQL до отправки уведомления в Telegram.
- Ошибка Telegram не должна приводить к потере уже созданного заказа.
- Вносить только запрошенные изменения и показывать результат после каждого этапа.
- Текущий прототип — ориентир интерфейса, а не готовый интернет-магазин.

## 17. Краткое итоговое решение

Для первой рабочей версии оптимальна связка:

```text
Домен REG.RU
        ↓
Виртуальный хостинг REG.RU
        ↓
HTML + CSS + JavaScript
        ↓
PHP
   ├── MySQL
   ├── административная панель
   └── Telegram Bot API
```

Такой вариант дешевле и проще VPS, поддерживает нужные функции и подходит для небольшого локального цветочного магазина. На VPS имеет смысл переходить только при росте нагрузки или появлении функций, которые невозможно нормально запустить на обычном хостинге.
