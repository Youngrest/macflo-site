## 1. Что это

Демо-сайт для маленькой цветочной студии **MAC.FLO** в Екатеринбурге (Instagram @mac.flo_studio, Telegram https://t.me/macflo66). У студии нет сайта и витрины, заказы принимают в Telegram. Продают: букеты, корзины с цветами, клубнику в шоколаде, макаруны; много собирают под заказ.

Сайт нужен, чтобы **продать его владельцу** как готовое решение. Сейчас это статический фронтенд (HTML/CSS/JS) без сервера, но с рабочими заявками в Telegram. Следующий этап после согласия заказчика — PHP-бэкенд + MySQL + админка на хостинге REG.RU.

## 3. Как запустить локально

На машине нет Python и Node. Есть PowerShell.

```
powershell -ExecutionPolicy Bypass -File serve.ps1
```
→ http://localhost:8765/. Или просто открыть `site\index.html` двойным кликом (шрифты подтянутся из Google Fonts при наличии интернета).

## 5. Дизайн — что решено и почему

Заказчик (Кирилл, владелец проекта, не владелец магазина) утвердил:

- **Стиль:** светлый «инста-магазин», нежные тона. Палитра: бумага `#f6f3ec`, поверхность `#fffdf9`, чернила `#1f251f`, зелёный `#254638` (кнопки), шалфей `#dfe6d3`, пыльная роза `#efd3d6`, ягодный `#b8515f`.
- **Шрифты:** Playfair Display 600 (заголовки, «престижный, не тонкий») + Manrope (текст). Google Fonts.
- **Формы:** скруглённые — карточки 18–24px, кнопки-пилюли.
- **Hero:** фото на весь экран в скруглённой рамке, при скролле сжимается (`--hero-p` 0..1 из JS), текст растворяется. Затемнение усиленное — заказчик просил, чтобы текст читался.
- **Под hero — ряд кнопок-категорий** (Букеты · Клубника в шоколаде · Макаруны · Букет на заказ · Корзина на заказ). Раньше были кружки как сторис — заказчик отверг. Активная подсвечивается через IntersectionObserver.
- **Нет** плашки «принимаем заказы до 20:00» — убрана по просьбе.
- **Мобилка:** нижняя панель Каталог / На заказ / Telegram / Корзина.
- **Десктоп (≥1080):** контейнер 1280, клубника — заголовок слева (sticky) + 2 карточки справа, «на заказ» — две широкие горизонтальные карточки (вторая зеркально), макаруны — горизонтальный блок.

## 6. Как устроен код

### `config.js`
`window.SHOP = {...}` — имя, город, `telegramLink`, доставка, массив `products`. Каждый товар: `{ id, group: 'bouquets'|'berries', name, note, price, image, badge? }`. `badge`: «Хит» (розовый), «Новинка», «Сезон». В конце `...(window.SECRETS || {})` — подмешивает токен из `secrets.js`.

### `secrets.js` (локально, не в git)
```js
window.SECRETS = { telegramBotToken: '…', telegramChatId: '…' };
```
Бот: **@macflo_orders_bot** («MAC.FLO заказы»), создан через BotFather. Chat ID сейчас — личный ID Кирилла. На GitHub Pages файл создаёт workflow из секретов репозитория `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Файл грузится **до** `config.js`.

### `app.js` — блоки
- Плейсхолдеры: если `<img>` не загрузился → обёртке `.media` добавляется `.ph` и подпись «нет фото · имя-файла».
- `[data-tg-link]` — всем таким ссылкам подставляется `SHOP.telegramLink`.
- Hero-скролл: пишет `--hero-p` в `:root`.
- Каталог: `[data-products="группа"]` заполняется карточками из `SHOP.products`.
- Корзина: `Map` в памяти + `localStorage['macflo_cart']`. Кнопка «В корзину» → степпер −/+. Drawer справа с тремя видами: items / checkout / success.
- Оформление: имя, телефон, доставка/самовывоз, адрес, дата (min = сегодня), время (10–13 / 13–16 / 16–20), открытка, комментарий. Номер заказа — счётчик в `localStorage['macflo_order_no']`, начинается с 101.
- `sendTelegram(text)` — `fetch` на `api.telegram.org/bot<token>/sendMessage` прямо из браузера. Если токена нет — имитация с задержкой 600 мс и `console.info`.
- Модалка «на заказ» — одна на четыре типа, конфиг `KINDS` в `app.js`:

| kind | заголовок | 1-я группа чипсов | 3-я группа | 4-я группа |
|---|---|---|---|---|
| `bouquet` | Букет на заказ | Бюджет | Оттенки (цветные точки) | — |
| `basket` | Корзина на заказ | Бюджет | Что внутри | — |
| `berries` | Коробка с ягодами | Бюджет | Шоколад | — |
| `macarons` | Набор макарун | Количество | Цвета | Вкусы (мульти) |

  «Повод» общий. У каждого типа своя подсказка в поле «Пожелания». Открывается через `[data-open-custom="kind"]`. Форма сбрасывается при каждом открытии.
- Кнопки категорий: IntersectionObserver подсвечивает активную.

### `styles.css`
Mobile-first. Переменные в `:root`. Брейкпоинты: `720` (планшет, 3 колонки), `900` (десктоп: убирается нижняя панель, появляется topnav), `1080` (4 колонки, расширенная десктопная раскладка), `1440`. Секции имеют `scroll-margin-top` под sticky-шапку.

### Фото
Оригиналы в `photos/`, маппинг «имя на сайте → исходный файл» в `prepare-photos.ps1`. Скрипт сжимает через System.Drawing (hero 2000px, карточки 1400px, превью 800px, JPEG 82). Чтобы добавить фото: положить в `photos/`, дописать строку в `$map`, запустить скрипт.

**Не хватает фото:** клубника в шоколаде *без* цветов (сейчас только «с цветами» и черешня).

## 7. Что дальше (после «да» от магазина)

Расходы: домен .ru на REG.RU — 169 ₽/год (акция, обычно 226 ₽); хостинг Host-0 — 420 ₽/мес или 5 038 ₽/год (PHP, MySQL, SSL, бэкапы). Итого ~5 200 ₽/год. Host-Lite дешевле, но без PHP/MySQL — не подходит.

План бэкенда — в `flower_shop_project_handoff.md` (разделы 8–11, 14): таблицы `categories, products, orders, order_items, admins, banners`; PHP 8 + PDO; `/admin/` с логином; заказы пишутся в MySQL **до** отправки в Telegram; сумма пересчитывается на сервере; токен бота уходит в PHP-конфиг вне публичной папки.

Текущий фронтенд к этому готов: `fetch` в Telegram заменяется на `fetch` в `order.php`, `config.js` заменяется выводом из базы, всё остальное остаётся.

## 8. Правила для ИИ (GPT, Claude и др.)

1. **Не переделывай дизайн.** Палитра, шрифты, структура секций, hero-эффект, кнопки-категории — утверждены заказчиком. Меняй только то, что попросили, точечно.
2. **Не возвращай то, что убрали:** кружки-сторис, плашку «принимаем заказы до 20:00», цены на макаруны, карточки без фото, вкладки в кондитерской.
3. **Не трогай `secrets.js`, `.gitignore`, `.github/workflows/pages.yml`** без прямой просьбы. Токен бота никогда не вставлять в `config.js`, `index.html`, `app.js` или любой файл, который попадает в git.
4. **Товары и цены — только в `config.js`.** Не хардкодить карточки в HTML.
5. **Новые фото — через `photos/` + `prepare-photos.ps1`.** Не класть оригиналы по 500 КБ в `site/img/`.
6. **Не предлагать Node.js, React, сборщики, фреймворки, Docker, VPS.** Проект — статика сейчас, PHP + MySQL на обычном хостинге потом. Так решено, аргументы в `flower_shop_project_handoff.md`.
7. **Не менять контакты** (телефон, адрес, график, ссылку TG) — они реальные и согласованы.
8. **Проверяй мобильную версию** после любой правки CSS — заказчик смотрит с телефона в первую очередь.
9. **Не коммить и не пушить без просьбы.** Локальные правки — да, `git push` — только когда сказали.
10. **Если чего-то не знаешь про проект — спроси, а не выдумывай.** Особенно про цены, условия доставки и что хочет магазин.

## 9. План бэкенда — ЖДЁМ ответов заказчика (на 17.09.2026 не начат)

Ничего из этого не делать, пока Кирилл не вернётся с ответами от магазина. Возможно, придётся переделывать после показа.

### Экраны админки (`/admin/`, под телефон)
1. Вход — логин + пароль.
2. Заказы — список (новые сверху), фильтр по статусу, карточка заказа, кнопка «позвонить», смена статуса: новый → подтверждён → собирается → у курьера → выполнен / отменён.
3. Заявки «на заказ» (букет / корзина / ягоды / макаруны) — отдельная вкладка.
4. Товары — список, добавить/изменить/скрыть/удалить, порядок перетаскиванием, загрузка фото с автосжатием, категория, бейдж.
5. Настройки — телефон, адрес, график, TG, доставка, тексты главной.
6. Акция/баннер — вторая очередь.

### Поток заказа
браузер шлёт товары + контакты (без суммы) → PHP проверяет товары и цены по базе, считает сумму сам → пишет заказ в MySQL, даёт номер → шлёт в Telegram (ошибка TG не теряет заказ) → показывает «Заказ №N принят».

### Этапы
0. Локально (нужно поставить PHP на комп Кирилла) — серверная часть + админка, ~3–4 дня. Хостинг не покупаем.
1. После «да»: домен + Host-0 (~5 200 ₽/год), заливка, HTTPS, домен — ~1 день.
2. Наполнение реальными ценами/фото через админку, обучение владельца 20 мин.
3. Запуск.
